零、实验后修订：旧路线为什么需要降级

旧路线是在大规模实验之前制定的。当时的假设是：ELF 已经能作为语言 latent flow 稳定生成文本， 因此最有价值的研究主菜是把 32/64 NFE 压到 1-8 NFE，同时用 PPL 和 context 扩展做支撑。

现在已经有了更直接的诊断结果。它们改变了问题定义：

实验观察含义对旧路线的影响
Clean decode 接近满分 DLM head 能从真实 target latent 解回 token，decoder 不是当前主瓶颈。 继续只强化 decoder 或只看 CE loss 意义有限。
Controlled denoise 在低/中噪声可用 模型在真实 bridge 附近能利用 prompt 修 target，不是完全忽略 condition。 低噪声 repair 不能代表 full generation 成功。
Full Tulu3 SFT 从纯噪声采样失败 模型会生成英文，但经常不按 prompt 回答；崩点在 high-noise semantic routing。 直接做 NFE 蒸馏可能只是在蒸馏一个不可靠 trajectory。
Short-QA 128 能从 t=0 训通 当前 CFM 代码路径并非理论上无法做 conditional generation。 问题更像数据分布、loss 配比、高噪声监督和 condition binding，而不是范式直接失败。
Tulu Short/Mixed 10K 暴露离散答案漂移和语义盆地偏移 真实 SFT 分布下，长 prompt、离散答案、模板任务、开放回答混杂会让 vector field 学到“合理答案流形”，而不是当前 prompt 的 target latent。 当前主问题应定义为 CFM instruction tuning 的可靠性，而不是采样器加速。
Stage-2 VQA probe 不可用 多模态模型能生成文本，但没有稳定按图/按问题回答。 多模态 Stage 1/2 不应继续盲目扩大，必须先修 text-only conditional flow。
新的核心问题： 连续 latent flow 语言模型能否通过合适的训练目标和数据阶段，稳定学会 condition + pure noise → prompt-specific target latent？ 如果这个问题没解决，NFE↓、多模态理解和长 context 都会建立在不可靠的生成轨迹上。

零点五、修订后的研究主线

修订后的 paper / 项目路线不再从“如何更快采样”开始，而是从“如何让 CFM 在语言 instruction 场景中可靠 conditional generation”开始。 旧的 NFE 方向仍然重要，但它应该跟在可靠 trajectory 之后。

主线 1

CFM SFT 诊断与可靠性

固定 clean decode、controlled denoise、t_start=0 trajectory、zero/shuffled gap、A/B/C gate。

目标： 不再让 loss 或 clean decode 误导训练判断。

主线 2

High-noise conditional flow

在 t=0~0.3 强化 condition routing：timestep 分布、loss weight、token-aware endpoint loss、trajectory consistency。

目标： 从纯噪声能按 prompt 进入正确 answer basin。

主线 3

Conditioned pretrain

在 SFT 前加入 prefix continuation pretrain，让模型先大规模学习 prefix + noise → continuation。

目标： 缩小 unconditioned OWT pretrain 到 instruction SFT 的能力断层。

新 Phase任务数据成功信号
Phase 0 · 固定诊断闭环 把 CFM SFT eval harness 当作所有实验 gate。 Tulu Short 10K / Tulu Mixed 10K / synthetic short QA / VQA probe。 每个 checkpoint 都能按 slice 输出 clean、high-noise gap、trajectory、exact/semantic 指标。
Phase 1 · 修 text-only conditional flow Recipe ablation：high-noise reweight、decoder_prob、EOS/length、source mix、token-aware loss。 先 Tulu Short/Mixed 10K，不直接 full Tulu3 盲训。 t=0.1 correct 提升，zero/shuffled 仍低；t_start=0 trajectory 同步改善。
Phase 2 · Prefix continuation pretrain 从 raw text 构造 prefix/continuation 条件生成任务，使用和 SFT 一致或兼容的 CFM loss。 OWT / 38b_solar / experiment_1997 过滤子集。 模型在非 instruction 数据上学会 condition controls generation，再迁移到 Tulu SFT。
Phase 3 · Instruction SFT 重训 用 Phase 1/2 选出的 loss 和 checkpoint 重新 SFT。 Full Tulu3 filtered + carefully balanced source mix。 短答案、自然短答、长答案 gate 都不靠 clean decode 虚高；生成按 prompt 回答。
Phase 4 · NFE / shortcut 加速 Token-CE distillation、stride-conditioned shortcut、MeanFlow/consistency 类目标。 以可靠 text-only checkpoint 作为 teacher。 在 NFE 1/4/8/32 上画质量-成本 Pareto curve。
Phase 5 · 多模态回归 SigLIP2 projector warmup + multimodal instruction finetune。 LLaVA / VQA / image-text 数据。 shuffled-image control 低于真实图像；回答不只是语言 prior。
修订后的 paper framing： 从 “token-aware accelerated flow matching for language” 调整为 “reliable conditional flow matching for language instruction tuning”， NFE 加速作为在可靠 conditional trajectory 上进一步成立的第二贡献。
下面的一、二、三、四、五、六、七、八、九节保留原始 NFE/PPL/context 规划。 这些内容仍有研究价值，但需要理解为实验前路线和 Phase 4+ 技术储备； 不再是当前立即执行的主线。

一、历史方案保留：先把 "NFE" 这个词的语义钉死

NFE = Number of Function Evaluations，整段序列共享。 ELF 报的 32 NFEs 不是 "一个 token 32 步"，而是 "整个 max_length=1024 的 latent 张量做 32 步 ODE/SDE 去噪"。每一步对 (B, 1024, d) 整段做一次双向 attention forward，生成完成后再加 1 次 DLM decode forward 得到 1024 个 token id。
范式生成 1024 tokens 的 forward 次数每次 forward 的算力
AR (GPT-2)1024（kv-cache 让单步便宜）O(S·d²)（增量）
ELF SDE-32~33（32 + 1 DLM）O(S²·d) 整段双向 attention，单步重
elf-pro 目标≤9（8 + 1 DLM 或更少）同上，仍是整段

这意味着两件事：

  1. "NFE↓" 不等于 "wall-clock 同比例↓"，因为 ELF 单次 forward 比 AR 重很多。但 NFE 是 paper 上最干净的 metric，与 solver / distillation 文献完全可比。
  2. max_length 是固定预算 — 想生成更长的文本必须在训练时把 max_length 拉大，这就把 context 扩展 自然带成了 elf-pro 的支撑性贡献。

二、历史方案：三条研究主轴 speed / scale / perf

主菜 · speed

NFE → 个位数

32 → 8 → 1-2，把生成成本降一个数量级。

为什么是主菜： ELF 已经把 SC-CFG 蒸馏进权重了，等于做了"半个 distillation"，从这里走 NFE 蒸馏是天然延伸；paper 上的故事最锐利。

支撑 · scale

Context 1K → 4K+

RoPE 外推 + 长序列数值稳定性 + 双向 attention 的内存代价。

为什么是支撑： Flow matching LM 在 4K+ 上没有先例，是开放问题；但本身是研究风险点，单独拿出来做主菜不安全。

支撑 · perf

PPL 24 → ≤21

P4 x-pred / P7 双 EMA / P5 SC-CFG sc_w 优化等。

为什么是支撑： 直接给 NFE 蒸馏提供更强 teacher；本身在 ELF-B 同参数同数据下卷指标，paper 卖点不够锐但 ablation 价值高。

三、历史方案：三轴的耦合关系

结论性顺序： 先 PPL（Phase 1）→ 再 NFE（Phase 2）→ 最后 Context（Phase 3）。 这不是按主菜重要性排，而是按依赖关系排。Phase 2 的蒸馏需要 Phase 1 的更强 teacher；Phase 3 的长 context 需要 Phase 2 的 NFE 砍下来后才在算力上合理。

四、Phase 4 技术储备：NFE 到个位数

4.1 ELF 的天然蒸馏起点

ELF 已经做了一件等价于"半个 distillation"的事 — 把 SC-CFG guidance 蒸馏到训练 target（train_step.py:175-184）：

v_target_guided = v_target + (1 − 1/sc_w) · (v_cond − v_uncond)

这意味着推理时不需要双 forward 跑 CFG。这条机制的精神可以直接迁移到 NFE 蒸馏：把 "32 步 teacher 的轨迹" 当成监督信号，训练 student 让单步预测更激进的 v。

4.2 候选技术对比

#方案NFE 目标难度paper 卖点关键风险
M1 Heun / DPM-Solver-2/3（无训练，纯换 solver） 16-8 同质量 易 弱（工程加速） 低 — 一阶 → 二阶 Euler 是经典做法，flow matching 有现成公式
M2 Consistency Distillation (CM/LCM) 4-8 中 中（已有大量先例，但 LM 上少） 需要 student + EMA target 双模型；训练 stable 性 OK

4.3 推荐主线：M1 → M2 → (M4 或 M5)

三段式打法：
  1. M1 当地板：先把 Heun / DPM-Solver-2 接上，看 flow matching 一阶 vs 二阶在 ELF 上能从 32 步推到几步还保 PPL。这是"无训练"的免费收益，paper 里作为 baseline。
  2. M2 当主菜：用 Phase 1 训出来的 PPL=21 模型作 teacher，做 consistency distillation 到 8 步、4 步。这是 paper 的中坚证据。
  3. M4/M5 当锦上花：如果 M2 跑通且时间允许，进一步推到 1-2 步。这步成功就是顶会标配。

五、后续支撑：context window 扩展（1K → 4K+）

5.1 当前状态

  • 所有 OWT YAML max_length: 1024（paper 原始 128 那条 review doc 已过时）。
  • RoPE (layers.py:50-96) 是固定 pt_seq_len = max_length，没有 NTK / YaRN / longrope。
  • 双向 attention → context↑ 直接吃 O(S²) attn 算力 + O(S·d) latent 内存；1K→4K 是 16× attn 算力。

5.2 开放问题（这就是 paper 的故事点）

问题已知 / 未知elf-pro 角度
双向 RoPE 外推 AR 场景有 NTK/YaRN/longrope 一堆方案；双向 attention 上没人系统验证过 原创性贡献点 — 至少做 NTK + position-interpolation 两版对比
v-target 数值稳定性 v = (x − z) / clamp(1−t, t_eps)，长序列 t≈1 段累积误差未知 由 P4 (x-prediction 参数化) 直接绕开 — 这是 PPL 工作和 context 工作共享的基础设施
Self-cond 在长序列上是否还能学 未知；x_pred_prev 维度从 1K→4K，attention 注意力分布漂移 需要 ablation：sc_prob ∈ {0.0, 0.25, 0.5} × max_length ∈ {1K, 2K, 4K}
训练显存 1K bf16 ELF-L 单卡 batch=64 已经要 grad-checkpoint；4K 要 FSDP2 L5 FSDP2 是 prerequisite

5.3 推荐打法

  1. 1K → 2K（短跑验证）：保持 ELF-B / OWT，仅改 max_length=2048，跑 1 epoch 看 loss 是否仍单调下降。这一步验证"flow matching 在 2K 不发散"。
  2. 2K → 4K（with RoPE 外推 ablation）：对比 (a) 直接增大 pt_seq_len 重训 (b) NTK-aware 缩放 (c) position interpolation。
  3. (可选) 切换语料：OWT 平均 ~700 tokens，2K 已经接近其上限；要做 4K 实验最好换 FineWeb-Edu 或 Dolma。

这一轴是 同参数同数据下卷指标，目的是给 Phase 2 NFE 蒸馏提供更强的 teacher。所有改动都在你确认过的"绿区"内（train_step.py + 周边）。

七、历史路线图（已被零点五节取代）

7.1 Phase 0 — baseline 复现（先决条件，并行处理中）

  • 由另一个 agent 处理：修复 HOPE 8gpu 上 dataset/tokenizer 加载 crash（HF HEAD 请求超时）。

7.2 Phase 1 — PPL teacher + 训练加速（绿区）

  1. 1a · S1 合 batch（中）：把 self-cond 的两次 no-grad uncond/cond forward 合成一次 2B forward。预期 -25~35% 训练时间，无指标变化。
  2. 1b · P7 双 EMA（易）：加 ema_decay2 = 0.999，eval 时 sweep 选最优。
  3. 1c · P4 x-prediction parameterization（中）：改 net_out_to_v_x 输出语义和 loss 形式，绕过 t→1 边界数值不稳。这一步是 context 扩展的前置。
  4. 1d · P5/P6 ablate（易）：SC-CFG sc_w 分布、decoder λ 分布。给 paper ablation 表填行。
  5. 目标：ELF-B Gen.PPL 24 → ≤21，作为 Phase 2 蒸馏的 teacher。

7.3 Phase 2 — NFE 蒸馏（主菜）

  1. 2a · M1 高阶 solver（易）：Heun / DPM-Solver-2 接上，看 32→16→8 步的 PPL 退化曲线。无训练，纯采样器升级。
  2. 2b · M2 Consistency Distillation（中）：用 Phase 1 PPL=21 teacher 蒸馏出 8-step / 4-step student。这是 paper 的中坚 claim。
  3. 2c · M4/M5 Shortcut / MeanFlow（难，可选）：进一步推到 1-2 NFE。如果 2b 跑通且时间允许就上，作为 paper 的"top-shelf"对比。
  4. 目标：Pareto curve — 横轴 NFE ∈ {1, 2, 4, 8, 16, 32}，纵轴 Gen.PPL，证明 elf-pro 在每个 NFE 都打过 ELF baseline。

7.4 Phase 3 — Context 扩展（支撑）

  1. 3a · max_length 1K → 2K：ELF-B 短跑验证 flow matching 在 2K 上 loss 仍稳定。
  2. 3b · L5 FSDP2 + activation checkpointing（前置）：4K 训练显存需要 ZeRO-3 级别。
  3. 3c · max_length 2K → 4K + RoPE 外推 ablation：对比直接重训 / NTK-aware / position interpolation；这是 paper 第三块 claim 的内容。
  4. 3d · 数据切换：必要时换 FineWeb-Edu / SlimPajama。
  5. 目标：elf-pro 在 4K context + 8 NFE 仍能产生连贯文本，PPL 与 1K baseline 可比。

九、Phase 4 方向池：NFE 加速的 ELF-only 想法

§四给的 M1-M5 是 diffusion 加速文献的通用 menu。本节把它们落到 ELF 上，给四条只有 ELF 这种"连续 latent denoiser + 离散 DLM head + 共享 trunk"架构才能写出来的方向。每条都给出训练目标、落点文件、最小可行实验。

统一直觉： ELF 比 vision diffusion 多了一个东西 — DLM head。它在训练时被强制对噪声鲁棒（decoder_noise_scale=5.0），也是采样最后一公里的"离散化函数"。NFE 加速的所有突破点几乎都来自把 DLM head 当 first-class citizen 用，而不是当一个被动的尾巴。

9.1 一个反直觉：MTP 直接套不上来，但 MTP 的精神可以

DeepSeek-V3 / Meta MTP 那种 "每步多预测 K 个未来 token" 的设定，前提是 AR 一次只产 1 个 token。ELF 一次 forward 已经预测了全部 1024 token（更准确说：1024 个连续 latent，再被 DLM 一次性 argmax）。token 维度上 ELF 已经是 extreme MTP，没有空间再多预测。

但 MTP 的本质不是 token，是"用辅助预测做 representation 正则"。这点在 ELF 上的同构对应是"多 t 时刻预测"：

MTP（AR LM）ELF 上的同构对应
当前位置预测下 K 个 token当前 (z, t) 预测下 K 个 t 时刻的 x_pred — 即 lookahead head
训练时加 K 个辅助 head训练时加 K 个辅助 t-anchor 损失（共享 trunk）
强迫 hidden 编码长程语义强迫 trunk 编码长程轨迹信息
推理可丢可保留辅助 head推理时可走"跳 K 步"路径 → 直接降 NFE

9.2 方向 A — DLM-as-Confidence：token-level 自适应 NFE

主菜 易 不动权重 / 0 训练成本

动机

一段文本里，"the / a / and" 几步就能定下来；专有名词、复杂搭配需要多步。MaskGIT 在离散 diffusion 里干过这事，ELF 因为有 DLM head 可以无缝迁移。

算法

每步 i ∈ [0, N) 结束:
  z̃_i ← ODE/SDE step
  logits_i = DLM_head(z̃_i)              # (B, S, V)
  conf_i   = softmax(logits_i).max(-1)   # (B, S), per-token confidence
  frozen_mask ←  (conf_i > τ_i) | frozen_mask  # 累积"已锁定"位置

  # 把已锁定 token 的 latent 替换为 embedding table 中对应 token 的 clean latent
  token_ids = argmax(logits_i)
  z̃_i[frozen_mask] ← x_clean_lookup(token_ids)[frozen_mask]
  # 后续步骤这些位置不再 diffusion（用 restore_cond 框架，复用 cond_seq_mask）

  if frozen_mask.all(): break  # 全部锁定 → 提前退出

实际效果预期

每步 frozen 比例随 t 增大而上升，越后期 active token 越少。平均 NFE = 32 步对应 cost 的 1/3 ~ 1/5，因为后半段稀疏化严重。

训练目标

不需要重训 — 这是纯采样器改造。可选改进：在训练时对"高 confidence 但仍在 noise 中的 token"加一个一致性辅助 loss，让 DLM 早期就敢做高置信预测。

落点

  • src/utils/sampling_utils.py：在 _ode_step / _sde_step 内部插入 confidence gate；token freezing 用 restore_cond 框架（已有）。
  • src/utils/generation_utils.py：_generate_samples_single_batch 主循环加 frozen_mask 状态。
  • src/configs/sampling_configs/*.yml：加 adaptive_nfe: true、conf_threshold 字段。

第一个实验

拿 ELF baseline (32-step SDE, PPL≈24)，加 confidence gate 但不重训，sweep τ ∈ {0.5, 0.7, 0.9, 0.95}。横轴平均 NFE，纵轴 Gen.PPL。预期：τ=0.9 时平均 NFE ≈ 8-12，PPL 退化 < 1。

风险

  • GPU batch 利用率下降：不同 sample 在不同步频被 freeze → batch 内不齐。缓解：用 mask 而不是 dynamic shape，被 freeze 的位置只是不更新但仍参与 attention（计算量没省，但 z̃ 不漂移）。真"省算力"要做 dynamic batching，是工程问题。
  • 早期 freeze 错误传播：t≈0.3 时 confidence 高但其实 token 错。缓解：confidence threshold 随 t 单调（早期严，后期宽）。

9.3 方向 B — Token-CE Distillation：直接监督 token，不监督 latent

主菜 中 这是 paper 最锋利的卖点

动机：现有 distillation 文献的盲点

Consistency Models / LCM / Shortcut 在 vision 上做 distillation 时，loss 永远是 latent 空间的 L2 / LPIPS：

loss_CD = ‖f_student(z, t) − stop_grad(f_teacher(z, t'))‖²

这在 vision 上没问题，因为最终输出就是连续像素。但在 ELF 上：latent 一致 ≠ DLM argmax 出的 token 一致，因为 DLM 是非线性的。两个 latent 的 L2 距离 ε 在 token 空间可能跨过 argmax 边界。

洞察： ELF 的最终目标是 token id，应该直接监督 token 一致性，而不是 latent 一致性。这是 ELF 这种带 DLM head 的架构能写出、vision diffusion 写不出的 distillation 目标。

训练目标

# Student: 1-step 或 K-step 模型
# Teacher: ELF baseline 32-step (frozen, EMA weights)

with torch.no_grad():
    z̃_teacher = teacher_sample(z₀, n_steps=32)         # (B, S, 512)
    tokens_teacher = argmax(DLM_teacher(z̃_teacher))    # (B, S)
    # 或者更严格：用 32-step 期间的 token sequence 作为多步监督

z̃_student = student_sample(z₀, n_steps=K)             # K ∈ {1, 2, 4, 8}
logits_student = DLM_student(z̃_student)               # (B, S, V)

# Token-level CE loss — 端到端对齐
loss_CE = F.cross_entropy(logits_student, tokens_teacher)

# 可选：附加 latent L2 作为正则
loss_L2 = ‖z̃_student − z̃_teacher‖² · λ

loss = loss_CE + λ · loss_L2

关键设计点：

  • Teacher 和 student 共享 DLM head（或者用同一份 frozen DLM），保证"token 标签"语义不漂移。
  • Teacher 用 EMA 权重 + 32 步 ODE/SDE 完整生成，student 用主权重 + K 步。
  • 这个目标天然兼容 SC-CFG（因为 DLM 已经吃过 SC-CFG 蒸馏的 trunk 表征）。

为什么这是 ELF-only 的 contribution

架构能否做 token-CE distillation
vision diffusion没意义（输出本来就是连续像素）
SEDD / Score-Entropy 离散 diffusion原生就是 token CE，但他们没有 latent；不存在"latent vs token"的二选一
continuous latent diffusion + retrieval decode（早期 LM diffusion）不可微的最近邻，无法做 CE 蒸馏
ELF (continuous latent + 学好的 DLM)独此一家：DLM 提供可微 token 监督

落点

  • 新建 src/distill_step.py：仿照 train_step.py 但改为 student-teacher 设置；teacher 用 EMA weights frozen，不参与 backward。
  • 新建 src/configs/training_configs/distill_*.yml：标 teacher_checkpoint、student_n_steps、distill_loss_weights。
  • train.py 加 distill mode 入口（参考 --mode distill）。

第一个实验

ELF-B teacher (Phase 1 训出来的 PPL=21 模型) + ELF-B student (相同初始化)，K ∈ {1, 4, 8}，对比三个 loss：

  1. Latent L2 only（vanilla CD baseline）
  2. Token CE only
  3. Token CE + λ·Latent L2

预期：方案 (3) 在 K=4 上 PPL 退化 < 2，方案 (1) 退化 > 5。这条对比就是 paper 的中心实验。

风险

  • Token CE 梯度比 latent L2 稀疏（argmax 边界附近的 latent 被推得很弱）。缓解：早期训练用 (3) 混合 loss，后期切纯 CE。
  • DLM head 在 1-step 粗糙 latent 上可能本来就乱码。需要先做 §9.5 的"DLM 鲁棒性 probe"验证可行性。

9.4 方向 C — Lookahead-MTP / Step-Conditional Shortcut Head

主菜 中 推 1-step 的最有希望路径

动机

把 §9.1 表格落地：让模型一次 forward 就能预测"跨 d 步"的 z 变化，而不是只预测 instantaneous v。这是 Shortcut Models (Frans 2024) 的核心，但 在 LM diffusion 上还没人做过。

训练目标 — Step-conditional flow map

把模型的输入从 (z, t) 改成 (z, t, d)，其中 d ∈ {1, 2, 4, ..., N} 是 stride。模型学习 d 步以后的状态：

# 原始 ELF：单步速度场
v_pred = model(z_t, t)
# z_{t+h} = z_t + h · v_pred  对小 h 准确

# Shortcut-ELF：直接预测 d 步以后的 x
x_pred_d = model(z_t, t, d)              # 直接学 d 步终态
target_d = z_{t + d·h}                   # 32-step teacher 跑到 t+d·h 的状态

loss_main = ‖model(z_t, t, d=1)·1 − v_target‖²    # 保留原 flow matching loss (d=1)
loss_shortcut = Σ_d ‖model(z_t, t, d) − x_pred_d_teacher‖²  # 多 stride 蒸馏

# 推理时：选 d=N 直接 1-step 完成

关键工程点：d 怎么进模型？

ELF 已有现成框架 — num_time_tokens=4 的 prefix-token 机制（model.py:97-105）让"t 作为 condition"成本是 4 个 prefix token。加 d 只需要新增 4 个 stride-token，几乎零改动：

class ELF(nn.Module):
    def __init__(..., num_stride_tokens=4):  # 新增
        ...
        self.stride_embedder = TimestepEmbedder(hidden_size)  # 复用 t 的 sinusoidal embed
        self.stride_tokens = nn.Parameter(torch.empty(1, num_stride_tokens, hidden_size))

    def forward(..., d=None):
        ...
        if d is not None:
            stride_emb = self.stride_embedder(d)  # (B, hidden)
            prefix.append(self.stride_tokens.expand(B, -1, -1) + stride_emb.unsqueeze(1))

训练 schedule

  1. Phase 1: 正常训 d=1（即 ELF baseline 训练）。
  2. Phase 2: 引入 self-distillation —— student 对每个 (z, t)，从已有权重生成 d ∈ {2, 4, 8, 16, 32} 的多步 teacher trace（no_grad），然后训 model(z, t, d) 学这些 trace。
  3. 这是同一个模型自己当自己的 teacher，类似 Shortcut Models 的 self-consistency。

与方向 B 的组合

Token-CE distillation + Stride-conditional 联合：

loss = F.cross_entropy(DLM(model(z, t=0, d=N)), tokens_teacher)
       + λ · ‖model(z, t, d=1) − v_target‖²    # 保 baseline 行为
       + μ · Σ_d ‖model(z, t, d) − x_d_teacher‖²

训练完一个模型，推理时根据延迟预算选 d：低延迟选 d=N (1-step)，高质量选 d=1 (32-step)。这是 paper "Pareto curve" 的来源。

落点

  • src/modules/model.py：ELF.__init__ 加 stride_embedder + stride_tokens；forward 加 d 参数。
  • src/train_step.py：训练 step 加 stride sampling（log-uniform d ∈ [1, N]）。
  • src/utils/sampling_utils.py：采样选 d=N 的快速路径。

第一个实验

ELF-B 上从头训一个 stride-conditional 版本（5 epoch baseline），然后 1-step 生成 vs 32-step 生成对比。预期：1-step PPL 比 32-step 退化 5-10 个点，但这就是 paper 卖点的起点 —— 进一步用方向 B 的 token-CE 把退化压回去。

9.5 方向 D — DLM 鲁棒性 Probe + 双 head 轨迹一致性

支撑 易 是上面三个方向的可行性前置

9.5.1 DLM 鲁棒性 probe（先做，~1 天）

方向 B/C 都隐含一个假设：DLM head 在远离 clean latent 的 z 上仍能给出有信号的 logits。这要先 probe 一下：

for σ in [0.1, 0.5, 1.0, 2.0, 5.0]:
    z_noisy = x₀ + σ · noise
    tokens_pred = argmax(DLM(z_noisy))
    accuracy = (tokens_pred == input_ids).mean()
    print(f"σ={σ}: token accuracy = {accuracy}")

预期（基于 decoder_noise_scale=5.0 训练）：

  • σ=0.5：accuracy > 95%（这是 ELF 训练 well within distribution）
  • σ=1.0：accuracy 70-90%（可用于 4-step distillation）
  • σ=2.0+：accuracy 退化但仍 >> 1/V（说明 DLM 学到了 robust 表征）

如果 σ=1.0 accuracy < 50%，说明方向 B 的 1-step distillation 有架构上的天花板，需要先 finetune DLM head 加噪。这就是 "warm-up DLM" 子任务：

# 用 ELF baseline trunk 冻死，单独 finetune DLM head 在更宽的噪声分布上
# 训练 1 个 epoch 即可，让 DLM 在 σ ∈ [0, 5] 上都鲁棒

9.5.2 双 head 轨迹一致性 loss

训练 distillation 时除了"终点 token 一致"（方向 B），还可以加"沿途每个 t 切片 DLM argmax 都一致"：

for t_anchor in [0.2, 0.5, 0.8]:
    z̃_t_teacher = teacher_step(z₀, target_t=t_anchor)   # teacher 的轨迹中点
    z̃_t_student = student_step(z₀, target_t=t_anchor, d=t_anchor/h)

    # 沿途 DLM argmax 一致性
    loss_traj += F.cross_entropy(
        DLM(z̃_t_student),
        argmax(DLM(z̃_t_teacher)).detach()
    )

这等于把 DLM 当 trajectory critic，给整条 ODE 轨迹打 token 级监督。"沿途 token 一致性"在现有 CD/LCM 文献里没人做过，因为 vision 没有这种"中间状态也可解码"的天然 critic。

落点

  • 9.5.1：写一个 standalone scripts/probe_dlm_robustness.py，独立运行，输出 σ-accuracy 曲线。
  • 9.5.2：在 distill_step.py 里加 trajectory anchor loss，t_anchors 随机采样几个。

9.6 整合：四个方向怎么排序进 Phase 2

9.7 Paper 故事的可写性自查

故事元素来自哪个方向是否 ELF-only
"现有 distillation 在 LM 上有结构性盲点"（latent 一致 ≠ token 一致）方向 B 的 motivation✅
"DLM head 提供原生离散监督信号"方向 B 的 contribution✅
"sequence-level adaptive compute"方向 A✅（配合 DLM）
"first systematic study of flow-map distillation in language modeling"方向 C✅
"trajectory-consistency loss using DLM as critic"方向 D 9.5.2✅
具体数字：NFE-1 PPL ≤ ELF baseline NFE-32A + B + C 联合—
历史结论（保留参考）： §九的四个方向仍然可以作为 Phase 4 的技术池， 尤其是 Token-CE Distillation、DLM trajectory critic 和 stride-conditioned shortcut。 但它们不再应该作为当前 paper 的第一主线；只有当 text-only conditional flow 的 t_start=0 trajectory 和 high-noise condition gap 被修起来后， 这些加速方法才有可靠 teacher 和可靠评价基础。
当前结论： elf-pro 的近期研究问题应改为 reliable conditional flow matching for language instruction tuning。 优先把 CFM SFT 训练成“从纯噪声按 prompt 到达正确 target latent”的模型； NFE↓、shortcut、MeanFlow 和多模态 instruction tuning 都应排在这条可靠性主线之后。
