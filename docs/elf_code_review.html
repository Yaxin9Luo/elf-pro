一、ELF 一句话回顾

ELF (Embedded Language Flows) 是连续 embedding 空间里的 flow matching 语言模型。整条流水线：

关键设计决策：

  • tokenizer / encoder 是 冻住的 T5-small（不参与训练）
  • 训练时一个 batch 里每条样本随机走 L2 denoiser 分支（flow matching, 80%）或 CE decoder 分支（cross-entropy at t=1, 20%）
  • 采样时只用 denoiser 的速度场积分到 t=1，最后用 decoder 头映射到 token
  • 有 Self-Conditioning（前一步 x_pred 作为输入）+ SC-CFG（self-cond CFG，把 sc 当作条件做 CFG 引导）

二、训练目标 / Self-Cond / CFG / 采样器

2.1 Flow matching 插值 & velocity 目标

sampling_utils.py:11-17 (add_noise) · train_step.py:120-121

z = t · x₀ + (1 − t) · ε · denoiser_noise_scale          # add_noise
v_target = (x₀ − z) / clamp(1 − t, t_eps)                # train_step.py:121

注意：这里和经典 RF 有两点不同：

  • denoiser_noise_scale 默认 1.0，但配置里是 config 字段，可以 ≠ 1（"分布扩展"），默认配 OWT 时 paper 似乎用了 2.0
  • t_eps = 5e-2，避免 t→1 时除 0；意味着最后 5% 的 t 段被裁掉，是个隐性 boundary。

2.2 Loss：CE / L2 混合（per-example branching）

train_step.py:104-110, 195-260 — 每条样本独立伯努利采 decoder_step_active∈{0,1}：

decoder_step_active ~ Bernoulli(decoder_prob)            # 默认 0.5（OWT 配置 0.2）
denoiser_t = t                                            # ε~logit_normal
decoder_t  = 1                                            # 始终 t=1
t_mixed = active·1 + (1-active)·t                        # 一次 forward 同时跑两套
z_mixed = active·decoder_z + (1-active)·denoiser_z

decoder_z = λ_t · x₀ + (1-λ_t) · noise · decoder_noise_scale,  λ_t = sigmoid(z_decoder)
Insight： 同一份 forward 两个 head 同时算（output, decoder_logits = model(...)），按 mask 选用，计算量没翻倍。但前向需要做 2 次「shared uncond + cond」（self-cond），实际每个 step 是 3 次 forward + 1 次 backward（具体见 §4.2）。

2.3 Self-Conditioning

核心想法：把上一步的 x_pred 拼到当前 z 后面作为输入（input dim = 2·encoder_dim）。model.py:88-89, 172-174：

self.self_cond_proj = Linear(2·encoder_dim → encoder_dim)
if x.shape[-1] == 2·encoder_dim:
    x = self_cond_proj(x)                                 # (z, x_pred) -> hidden

训练时：以 self_cond_prob（默认 0.5）启用，启用时 x_pred 来自一次 停止梯度的 forward；不启用时填 0。

2.4 SC-CFG（self-conditioning classifier-free guidance）

这是 ELF 的特色：把 "用不用 self-cond" 当作 CFG 的"条件 vs 无条件"。train_step.py:175-184

v_cond   = forward(z, x_pred)         # 用 self-cond
v_uncond = forward(z, 0)              # 不用 self-cond
sc_w     ~ log-uniform[0.5, 5.0]      # SC-CFG scale, sample_cfg_scale
v_target_guided = v_target + (1 - 1/sc_w) · (v_cond - v_uncond)

等价于把 v_target 朝 "更靠 self-cond 的方向" 拉。训练时直接监督 guided target，避免推理时再做两次 forward。这相当于把 SC-CFG 蒸馏进了模型，是 ELF 一个聪明的工程优化。

2.5 采样器：ODE 与 SDE

sampling_utils.py:211-251

采样器更新规则关键参数
ODE (Euler) z_{t+h} = z_t + (t_next - t) · v_pred 无
SDE (hybrid churn) α = 1 − γ·h ； z_back = α·z + (1-α)·ε（向后注入噪声） 然后再用 z_back, t_back=α·t 走一步 Euler γ (sde_gamma)
注意一个 bug-like 行为： sampling_utils.py:240-243 SDE 的随机噪声在 GPU 上没用 generator（torch.randn(..., device=z.device)），CPU 才用。这意味着 SDE 采样结果在 GPU 上不可严格复现，跑 ablation 时要么自己注入 generator，要么 fix seed 在 CPU。

3.3 输入路径（带 prefix tokens）

有意思的 trick：

  • Bottleneck text proj（layers.py:115-124）：512→128→hidden，把 T5 latent 先压到 128 维再扩张。这是 降参数 + 降 lr-sensitivity 的妙招，但也是潜在的 information bottleneck，见 §6 #P3。
  • Mode tokens（model.py:181-196）：每条样本独立 gate（mode_tokens × decoder_step_active），让模型「知道」当前是 denoiser 还是 decoder 模式。
  • Decoder unembedding 也走 bottleneck（model.py:131-140）：hidden→512(GELU)→vocab，和 input proj 不绑权重（论文里 "shared-weight" 是指 decoder mapping 在 t=1 一步到位的概念，不是字面权重共享）。

四、训练循环（train_step.py）拆解

4.1 一个 step 的完整数据流

  1. 编码：input_ids → x₀ via 冻 T5 encoder（bf16，no grad）
  2. 采时间：t ~ logit_normal(P_mean=0.8, P_std=0.8)，重尾偏向 t≈1（接近 clean）
  3. 构噪：denoiser_z = t·x₀ + (1-t)·ε；decoder_z = λ_t·x₀ + (1-λ_t)·ε·decoder_noise_scale
  4. per-example 选支：每条样本独立选 decoder/denoiser → mixed input
  5. self-cond init forward（compute_shared_uncond, line 142-151）：z + zeros 跑一遍，得 x_pred_init，no_grad
  6. self-cond cond forward（get_sc_cond_and_uncond, line 153-173）：z + x_pred_init 跑一遍，得 v_cond，no_grad
  7. 构造 guided v_target：v_target + (1-1/sc_w)·(v_cond - v_uncond)
  8. 主 forward（line 224-230）：(z_mixed, x_pred_cond) + t_mixed，同时出 v_pred 和 decoder_logits
  9. 合 loss：(ce·ce_mask + l2·l2_mask) / total_mask，单分母
  10. backward + clip + EMA

4.2 Forward 次数（重要！）

场景每个 step 的 forward 次数
self_cond_prob = 0, sc_cfg_tokens = 01（主）
self_cond_prob > 0, sc_cfg_tokens = 02（init no_grad + 主）
self_cond_prob > 0, sc_cfg_tokens > 0（默认）3（uncond no_grad + cond no_grad + 主）
这是 ELF 训练慢的核心原因之一。 每个 optimizer step 实际有 2 次 no-grad forward + 1 次主 forward + backward。如果 backward 占比 ≈ forward 的 2x，那理论上一个 step 的算力是 2F + 1F + 2F = 5F，其中 2/5 = 40% 的算力花在 no-grad self-cond 前向上。这是 §6 #S1 的来源。

4.3 优化器配置

  • 默认 optimizer = "muon"（Keller Jordan 的 Muon）
  • 可切 AdamW，β=(0.9, 0.95)，wd=0.0
  • blr=5e-5（base lr，effective = blr · batch_size / 256）
  • lr schedule = constant（这其实很激进，没 warmup-decay）
  • EMA decay = 0.9999（单条 EMA）
  • grad clip = 1.0

条件每步 forward 次数
无 self-cond, cfg=11

这是 ELF 真正的工程亮点： 推理时 SC-CFG 不需要双 forward，因为它已经被监督到训练 target 里。这给 elf-pro 的 speed 优化定了基线 — 想超过 ELF 的速度，只能从「采样步数 / 模型本身效率」下手。

六、可改进点清单

以下每条标注：PERF = 性能 / SPEED = 速度 / SCALE = 规模；以及难度（易/中/难）和风险。

6.1 性能维度（Gen.PPL ↓ / Entropy ↑ / 任务指标 ↑）

#问题诊断改进建议难度
P1 encoder 是 T5-small，512 维，旧 T5-small 是 2019 paper、English-only、句法/语义表示落后于现代 encoder。整个 ELF 的 latent 空间天花板就在这。 换 更强 encoder：① gemma-2b-encoder（如果存在）；② 自训一个 sentencepiece + Llama-tokenizer + small encoder；③ 用 BGE-M3 / E5-mistral 这种 sentence encoder（语义更紧致）；④ 干脆 跟模型联训（小步长 + lr scaling，破除"冻死"假设） 中
P2 双向 attention，没有 causal 信息 denoiser 可以双向看（合理）；但decoder 头也是双向，做 t=1 离散映射时丢失了 token 顺序的因果先验。AR 语言建模本质上是单向，强制双向会损失 1-3 点 PPL。 ① 引入 hybrid mask：denoiser 双向，decoder 头改 causal；② 或者尝试 prefix-LM 风格：condition 双向，target 因果。这是 elf-pro 一个明确的"原创性贡献点"。 中
P3 Bottleneck dim = 128 太小 T5-small 512维 → 强行压到 128维 → 768/1056/1280 hidden。压 4x 是为了省 input proj 的参数，但对语义敏感的语言任务可能丢信息。OOC：image diffusion 用类似 trick 是可以的，因为像素冗余高；语言不一样。 ① ablate bottleneck_dim ∈ {128, 256, 512(=no-bottleneck)}；② 或者用 低秩 adapter（LoRA-style）替代 bottleneck，参数量可控同时保留 full-rank capacity。 易
P4 t_eps = 5e-2 裁掉 5% 高 t 段 v_target 在 t→1 时数值爆炸（除以 1-t），所以裁掉。但裁掉的恰好是离 clean 最近的一段，对最终输出质量很关键。 ① 改用 x-prediction parameterization（直接预测 x₀），训练更稳；② 或者 logit-snr loss weighting（EDM 风格），让 boundary 自然过渡。 中
P5 SC-CFG 把训练 target 拉向 cond，但 sc_w 是 log-uniform [0.5, 5] 采样时 sc_w=3，但训练时 sc_w 跨度大且同一 batch 不同样本不同 sc_w，可能让模型学到一个过于"保守"的 target。 ① 改成 schedule-conditional sc_w（早期小、后期大），更贴近采样轨迹；② 或者训练时直接采固定 sc_w=3，看是否提升。 易
P6 decoder 分支用 logit-normal noise，但 P_mean=0.8 偏向 λ→1（很 clean） decoder 永远在 t=1 训练，但 z 又加 logit-normal 噪声混合 — 这是 ELF 论文里的 trick（让 decoder 更鲁棒），但 P_mean=0.8 → λ≈0.69 偏 clean，鲁棒性可能不够。 ablate decoder λ 分布：① 加大 P_std；② P_mean 调到 0；③ uniform。 易
P7 EMA 只有一条 (decay 0.9999) "single EMA" — paper 报的指标几乎肯定是 EMA 权重的。但 EDM2 的经验是双 EMA + post-hoc EMA-rate sweep能再提 1-2 点。 加第二条 EMA (e.g., 0.999)，eval 时 ensemble 或 sweep 选最优。 易

6.2 速度维度（训练吞吐 + 采样步数）

#问题诊断改进建议难度
S1 训练一个 step 要 3 次 forward（2 次 no-grad self-cond + 1 次主） 见 §4.2。是 ELF 训练慢的最大原因。 elf-pro 的 speed 头号目标。可选方案：
  1. 合 batch trick：把 uncond/cond 两次 no_grad forward 合成一个 2B 的 batch（layout 相同 → 一次 SDPA），预期省 30% wall-clock。
  2. 降低 self_cond_prob：从 0.5 → 0.25，砍掉一半 self-cond 触发，但要小心性能。
  3. cache uncond forward：在 grad-accum 步内复用 uncond hidden（不 100% equivalent，但接近）。
  4. fused single-pass SC training：用 mean-field self-cond（共享 trunk 出双头），避开重复前向 — 这是个研究 idea。
 中 ~ 难
S2 采样 32 步 SDE 偏多 32 步 SDE → 模型 forward 32 次（条件生成更是 64×2=128 次）。 ① Consistency distillation / shortcut models：把 32 步压到 4-8 步；② DPM-Solver/Heun 高阶求解器，理论上 16 步达 32 步质量；③ flow matching specific：MeanFlow / IMM（最新工作），1-2 步生成。 难
S3 没有 Flash-Attn 显式调用，依赖 SDPA backend F.scaled_dot_product_attention 在 PyTorch 2.x 上自动选 backend，但 BF16 + 长序列下未必命中 flash-attn-3。 ① 升级 PyTorch ≥2.5 / 用 torch.nn.attention.SDPBackend.FLASH_ATTENTION 显式指定；② 或者直接接入 flash-attn 的 cu_seqlens 接口（尤其变长 batch 时）。 易
S4 没有 GQA MHA 在大模型 scale 时 KV 占内存、attention 慢。Llama3 / Qwen 都是 GQA。 scale up 时换 GQA (kv_heads = heads/4 或 heads/8)。inference 还能省一倍 KV bandwidth。 易
S5 双向 attention 不能 KV-cache 采样时每步要重算所有 token 的 attention。 跟 P2 联动：如果改 prefix-LM，target 端因果就能 KV-cache（在生成式应用场景里这是大杀器）。 中
S6 SDPA 没用 FlashAttention 的 varlen 接口 OWT 是固定 max_length 的 padded batch，但条件生成（XSum）长度差异大 → padding 占算力。 变长场景启用 flash-attn varlen + cu_seqlens；padded scenario 不用动。 中

6.3 规模维度（推到 1B+ 并保 scaling law）

#问题诊断改进建议难度
L1 最大才 ELF-L 652M，远低于 1B+ 阈值 论文显示 ELF-L vs ELF-M 上 PPL 反而变差（23.3 vs 21.7），暗示已撞到某种瓶颈（数据量？lr schedule？bottleneck dim？） elf-pro 的 scale up 目标至少做到 1B / 3B / 7B 三个点。要先诊断 ELF-L 退化原因（很可能是 P3 bottleneck 或 lr_schedule=constant 或 OWT 数据量太小 → 过拟合）。 难
L2 OWT 数据集太小（~9B tokens） 5 epoch on OWT ≈ 45B tokens — 在 1B+ 模型规模下严重过拟合。 换更大 corpus：SlimPajama / Dolma / FineWeb-Edu。要重做数据 pipeline（pre-tokenize + sharded arrow）。 中
L3 固定 max_length=128 OWT 配置 128 token — 这是 toy 长度。现代 LM 至少 2K-4K context。flow matching 在长序列上的稳定性是 未被回答的研究问题。 ① 推到 max_length=2048+，研究 RoPE 缩放（pt_seq_len/ft_seq_len）；② 也是个 paper-worthy contribution。 难
L4 lr schedule = "constant"，warmup_steps=5000 之后就 flat scale up 时 constant lr 几乎肯定会发散或停滞。Muon 也不能救。 切 cosine + min_ratio=0.1 或 WSD (warmup-stable-decay)。后者在大模型预训练里是新主流。 易
L5 没有 ZeRO / FSDP 看 train.py 是普通 DDP（待验证）。1B+ 不开 ZeRO-2 直接 OOM。 引入 FSDP2 或 DeepSpeed ZeRO-3 + activation checkpointing。你的仓库 laionface-tokenzier 已经有现成的 DeepSpeed pipeline，可以借鉴。 中
L6 没有 MoE 路径 当前是 dense transformer，scale 到 7B+ 时 dense 的 compute/quality 比远不如 MoE。 可选支线：实现 MoE-ELF（DeepSeek-style fine-grained MoE），把 active params 控制在 1B 以内但 total params 7B+。这是高风险但有故事的方向。 难
L7 μP / 初始化没显式做 scale up 跨多档时，没用 μP 会导致每档都要重调 lr。 用 μP / Spectral parameterization，或者至少 inverse-sqrt depth scaling，让 ELF-B 调出来的 lr 直接迁移到 ELF-XL。 中

七、elf-pro 推荐路线图

Phase 0 — 复现 baseline（1 周）

  • 跑通 ELF-B on OWT，对齐 Gen.PPL ≈ 24, Entropy ≈ 5.15
  • 跑通 ELF-M / ELF-L，重现 ELF-L PPL 退化现象
  • 建立训练吞吐 baseline（tokens/sec/GPU）和采样 wall-clock baseline

Phase 1 — 速度先行（1-2 周）

  • S1：合并 uncond+cond no-grad forward → 一次 2B forward
  • S3：显式 Flash-Attn-3
  • S4：GQA
  • 目标：单 step 训练 wall-clock -30%~-40%

Phase 2 — 性能升档（2-3 周）

  • P2：hybrid mask（denoiser 双向 + decoder causal）
  • P3：bottleneck ablation
  • P7：双 EMA
  • P4：x-pred parameterization 或 EDM-style loss weight
  • 目标：ELF-B Gen.PPL 24 → ≤ 21

Phase 3 — Scale Up（4-6 周）

  • L4：cosine / WSD lr
  • L5：FSDP2
  • L7：μP
  • L2：FineWeb-Edu / SlimPajama 数据
  • L3：context 扩到 2K
  • 训出 elf-pro 1B / 3B，给 paper-grade scaling curve
  • S2 (蒸馏 / few-step) 作为可选支线

7.1 「全面超越 ELF」三个具体打击点（建议作为 paper claim）

  1. Speed：训练 step 加速 30%+（S1 合 batch + S3/S4），采样步数从 32 → 8 同质量（S2 蒸馏）；
  2. Performance：在 ELF-B 同等参数和数据下 Gen.PPL ≤ 21（vs ELF 的 24.1），来自 P2 hybrid mask + P3 bottleneck + P7 双 EMA 的组合；
  3. Scale：把 ELF 推到 1B / 3B 规模，画出干净的 scaling curve（vs ELF 在 ELF-L 退化），证明 flow matching 语言模型 能 scale。

7.2 风险与回避

风险缓解
SC-CFG 的"训练蒸馏"机制依赖精确数学，改动 self-cond 路径要小心 所有 self-cond / sc-cfg 相关改动都在 ELF-B + OWT 上 ablation 一遍
Flow matching 在 1B+ 长 context 上没有先例 分阶段 scale：128 → 512 → 2K，每档至少跑 short run 验证 loss 稳定
双向 attention 改 hybrid 可能破坏 paper 报的指标 纯 ablation：保留 baseline 的纯双向作为对照
FSDP2 / Muon 在大规模没充分验证 scale up 时切 AdamW + FSDP2 作为保底；Muon 留 ELF-B 验证
