Flow Matching 语言模型的 Teacher Forcing、x/v Prediction 与 Trajectory Gap

2026-05-31 讨论整理；2026-06-01 根据 Token-Level Semantic Supervision 实验更新。 本文把 AR Teacher Forcing、ELF/CFM 的连续 latent 训练方式、x-prediction / v-prediction 参数化、instruction SFT 失败模式、conditioned pretrain 与可落地修正方案放到同一张图里。

一句话结论

ELF 当前的核心问题不是“DLM decoder 读不出 target latent”，也不是“loss 没下降”。 更准确地说，是 Flow Matching 在真实 bridge state 上学到的局部 vector field， 没有稳定转化成从纯噪声出发、按 prompt 进入正确 answer basin 的 self-rollout 能力。 代码层面上，ELF 网络的直接输出已经是 x_pred，即当前 noisy latent 对应的 clean data latent endpoint 估计；v_pred 是后续为了 flow loss 和 ODE/SDE 更新再换算出来的量。 2026-06-01 的 semantic CE ablation 进一步确认：在高噪声 x_pred 上直接做 token-level endpoint supervision，可以把 Tulu Short 10K 的 t=0.1 controlled denoise 从约 0.67 拉到约 0.99。
AR

Teacher forcing 直接训练真实 prefix 下的 next-token 分布。

FM / CFM

训练时看真实 x0 加噪得到的 bridge state，推理时看模型自己走出的 state。

ELF-SFT

失败集中在高噪声 conditional routing，而不是 clean decode 或低噪声 repair。

x-pred

网络预测 clean latent endpoint；采样时再转换成 velocity 做积分。

AR Teacher Forcing 到底是什么

自回归语言模型训练时，模型在每个位置预测下一个 token，但它看到的历史前缀永远是数据里的 gold prefix，而不是模型自己前一步生成出来的 prefix。 

真实序列:
<BOS> The cat sat

训练输入:
<BOS> The cat

训练标签:
The   cat sat

所以训练目标是：

L_AR = - Σ_t log pθ(x_t | x_<t)

这个目标和 AR 模型的概率分解完全一致： 

pθ(x_1, ..., x_T) = Π_t pθ(x_t | x_<t)
因此，AR validation loss 下降通常是很强的信号：模型在真实文本前缀下给真实下一个 token 的概率变高了。 它仍然有 exposure bias，但训练目标本身和推理模型定义是对齐的。

Flow Matching 里的“类 Teacher Forcing”

Flow Matching 训练时也有一种连续空间里的 teacher-forced state。给定真实 target latent x0 和随机噪声 eps，训练输入来自真实答案桥： 

z_t = t * x0 + (1 - t) * eps
direct network output = x_pred_theta(z_t, t)
v_pred = (x_pred_theta - z_t) / (1 - t)
v_target = (x0 - z_t) / (1 - t)

这意味着模型在每个 noise level 看到的是“真实答案桥”上的中间状态。它学的是： 在这条真实桥附近，应该往哪个方向走。

这里要区分两个概念：网络直接输出什么，和 loss / sampler 最后在哪个空间工作。 标准 Flow Matching 常直接输出 velocity。ELF 则采用 x-prediction： backbone 输出 x_pred，再通过解析公式换成 v_pred 去算 flow loss 和更新轨迹。 因此它不是“每一步预测下一步 latent”，而是在每个 z_t 上预测同一个终点： 当前样本对应的 clean data latent。

范式 训练时输入 推理时输入 主要 mismatch
AR LM 真实 token prefix 模型自己生成的 token prefix 错 token 会进入非 gold prefix，但仍是合法离散文本前缀。
Flow Matching LM 真实 x0 加噪得到的 continuous bridge state 模型 rollout 得到的 continuous latent state 早期偏离后可能进入非自然文本轨迹，后续 vector field 在 off-trajectory latent 上工作。
所以，controlled denoise 通过只能说明模型在真实 bridge 附近会修。 它不保证模型从纯噪声开始时能自己找到那条 bridge。

x-prediction 和 v-prediction 的具体差别

在线性 rectified flow 路径里，x0、eps、z_t、v 可以互相换算。给定 z_t 和 t，只要模型预测得足够准， 直接预测 v 再换成 x，和直接预测 x 再换成 v 都是合法 generator。 

v = (x0 - z_t) / (1 - t)
x0 = z_t + (1 - t) * v

所以问题不是“velocity 不能 decode”。真正的问题是：数学最优解等价，不代表网络训练动态、 误差形态、容量需求和 decoder 接口等价。

维度 x-prediction v-prediction
网络直接输出 x_pred：当前 noisy latent 对应的 clean endpoint 估计。 v_pred：从当前 state 指向后续轨迹的速度/方向。
和 decoder 的关系 DLM head 看到的是“像 clean T5 latent 的对象”，接口自然。 必须先做 x_pred = z_t + (1 - t) * v_pred，再交给 DLM；raw velocity 本身不适合 decode。
目标语义 所有 timestep 都回归同一个 clean data latent，监督语义稳定。 高噪声时是全局 transport 方向，低噪声时是局部修正方向，同一个输出空间承担不同语义。
误差缩放 若用 v-loss 训练，x 误差会被 1 / (1 - t) 重新加权。 若直接用 v-loss，采样更新最直接，但转换到 token decode 时误差变成 (1 - t) * v_error。
语言任务风险 更容易把共享 backbone 和 DLM decode 绑定到 clean latent manifold。 模型容量可能花在表示 off-manifold 的 noised quantity；对共享 decode head 不友好。
ELF 当前采用的折中是：网络输出 x_pred，训练和采样仍通过 v_pred = (x_pred - z_t) / (1 - t) 回到 velocity field。 这保留了 Flow Matching 的 ODE/SDE 生成方式，同时让模型显式输出落在 clean latent 语义空间。

为什么何恺明他们强调 x-prediction

Li & He 的 Back to Basics: Let Denoising Generative Models Denoise 核心论点是：自然数据通常位于高维观察空间中的低维 manifold 上，而 noise / velocity 这类 noised quantity 不在这个 clean data manifold 上。让网络直接预测 clean data，可以让有限容量模型优先学习低维结构， 而不是保存和重构高维噪声细节。

论文里的关键实验也不是单纯说“换一个 loss 权重就行”。在 ImageNet 256、JiT-B/16 设置下， 每个 patch 是 768 维，已经接近 Transformer hidden size；这时只有 x-prediction 在三种 loss space 下都能正常工作，eps-prediction 和 v-prediction 会出现灾难性失败。作为对照，低分辨率 JiT-B/4 的 patch 只有 48 维，三种 prediction space 差距就小很多。这个现象支持他们的判断：问题不只是 loss weighting，而是高维 noised quantity 对网络容量和信息保留提出了更硬的要求。

该论文还明确区分 prediction space、loss space 和 generator space： 网络可以直接输出 x、eps 或 v，loss 也可以定义在不同空间； 推理时则总可以把输出变换到 v 空间再解 ODE。也就是说， x-prediction 不是放弃 vector field，而是把“网络直接要学的对象”改成 clean data endpoint。 

# JiT / ELF 风格的核心步骤
z_t = t * x0 + (1 - t) * eps
x_pred = net(z_t, t)
v_pred = (x_pred - z_t) / (1 - t)
z_next = z_t + h * v_pred

这和本代码库是一致的：src/modules/model.py 的 final_layer 返回 backbone 的 clean latent prediction； src/utils/sampling_utils.py 的 net_out_to_v_x 再把它换成 v_pred。 src/train_step.py 训练 denoiser 分支时，也是在这个转换后的 v_pred 上和 v_target 做 L2。

这对 ELF 语言建模意味着什么

图像里的 clean endpoint 是像素或图像 latent；ELF 里的 clean endpoint 是 frozen T5 encoder 产生的上下文化 token latent。ELF 选择 x-prediction 的直接收益，是让同一个共享 trunk 同时服务两件事： 一边在连续 latent 空间里 denoise，一边在 decoder mode 下把 latent 投到 vocab logits。 如果直接预测 v，也能通过公式换回 x，但 raw output 本身就不再是 decoder 应该消费的对象。

这也解释了为什么“clean decode 很好”仍然不等价于“flow 生成很好”。 x-prediction 让每一步都有一个可 decode 的 endpoint 估计，但如果高噪声处的 endpoint 选错了 answer basin， 后续 ODE 只是沿着错误语义继续精修。

为什么语言比图像更容易暴露这个问题

图像 pixel/latent space 的局部几何相对平滑。即使用 x-prediction，采样时仍会转换成 vector field 做 rollout；在图像里，vector field 的小误差通常仍会把样本推向一个相近图像区域， 后续步骤还有机会修正。

语言 latent 则不同。最终输出要经过 DLM head 的 token argmax。连续 latent 的小偏移可能跨过离散 token 边界，尤其是数字、yes/no、标签、实体名、短答案这类信息密度很高的 target。

错误类型 图像 FM 中的表现 语言 ELF 中的表现
局部 vector field 小偏差 图像轻微模糊、纹理变差、构图偏一点。 数字、label、实体或首词变成另一个合法但错误的 token。
高噪声语义盆地选错 可能仍是同类对象或相近图像。 生成“合理回答”，但不是当前 prompt 的答案。
多步 rollout 累积 后续步骤可能继续朝图像 manifold 修。 进入错误 answer basin 后，低噪声修复只是在错误语义上精修。

当前 ELF 证据链

最新诊断见 elf_multimodal_scaling_plan.html 和 cfm_sft_eval_harness.md。 关键信号是：

  • Clean decode 好：真实 target latent 经 DLM head 能还原 token，说明 decoder 不是主因。
  • Controlled denoise 好：从 target latent 加噪后，correct prompt 明显优于 zero/shuffled prompt。
  • Full rollout 差：从纯噪声 t_start=0 起步时，经常生成英文但答非所问。
  • 采样 schedule 是次要因素：uniform 和 logit-tail 在高噪声失败模式相近。
  • 真实 Tulu 分布更难：synthetic short QA 能训通，Tulu Short/Mixed 暴露离散答案漂移和语义盆地偏移。
  • Semantic CE 已验证有效：固定 denoiser_p_mean=-3 后，在 t<=0.30 的 denoiser branch 上加 CE(DLM(x_pred), target_tokens)，能显著修复高噪声语义方向。
只看 loss、clean decode 或低噪声 denoise，会误判 checkpoint 已经学会 instruction following。 CFM SFT 的硬指标必须包含 t_start=0 trajectory 和 high-noise condition gap。

一步生成能不能解决错误累积

如果模型真的能在 t=0 从纯噪声一步预测出可 decode 的 clean latent，那么它确实可以避免多步 vector field 误差累积。 

多步:
z_0 noise -> z_0.1 -> z_0.3 -> ... -> z_1 -> DLM decode

一步:
z_0 noise -> x_pred ~= target clean latent -> DLM decode

但一步生成不是免费午餐。它把问题从“局部速度准不准”变成“全局 transport map 准不准”。 对语言来说，这要求模型在最高噪声处就选中正确 answer basin。

ELF 当前模型形式上已经可以做 t=0 direct x_pred decode： 因为网络输出就是 x_pred。真正问题是 x_pred(t=0, prompt) 是否足够可靠。

如果模型直接输出的是 v_pred，一步 decode 仍然可以做，但必须先转换： x_pred = z_t + (1 - t) * v_pred；在 t=0 时就是 x_pred = z_0 + v_pred。ELF 当前采用 x-prediction，所以 direct decode probe 更直接：它检查的正是模型在最高噪声处给出的 clean endpoint 是否已经可读。

Pretrain 阶段为什么看起来没这个问题

严格讲，无条件 pretrain 也有 Flow Matching 的 train/inference state mismatch。 但它没有 instruction SFT 中最致命的 conditional binding 问题。

阶段 训练目标 失败是否容易暴露
Unconditional pretrain noise -> 某个像 OpenWebText 的文本 latent 不要求对应某个指定答案。trajectory 漂到另一个合理文本区域，PPL/entropy 可能仍可接受。
Instruction SFT prompt + noise -> 当前 prompt 的 answer latent 必须按 prompt 进入唯一或少数正确 answer basin。数字、label、实体一错就是任务失败。

因此，当前问题更像是：无条件 text prior 会说话，但 conditional transport p(answer | prompt) 没学稳。

Conditioned Pretrain / Prefix Continuation Pretrain

Prefix continuation pretrain 和 instruction SFT 在代码形态上很像，都是： 

condition_input_ids = 条件部分
input_ids = 要生成的 target 部分

但二者语义不同。

Prefix continuation pretrain

自监督 大规模

原文:
The city council approved the new transit plan after months of debate.
The proposal will add new bus lanes downtown.

condition:
The city council approved the new transit plan after months of debate.

target:
The proposal will add new bus lanes downtown.

目标是让 flow 学会“给定自然文本前缀，继续生成后文”。

Instruction SFT

监督 任务化

condition:
User: What is 39 minus 10?
Assistant:

target:
29

目标是让模型学会任务格式、回答偏好、拒答、安全、标签、数学等行为。

AR pretrain 天然就是 prefix -> next token。ELF 的无条件 pretrain 没有充分训练 “condition 控制 generation” 这件事，所以在 OWT pretrain 和 Tulu SFT 之间加 prefix continuation pretrain 是合理的中间阶段。

修正路线

优先级 方向 要修的问题 具体做法 风险
P0 固定诊断闭环 避免继续被 clean decode / loss 误导。 每个 checkpoint 固定跑 clean、controlled denoise、t_start=0 trajectory、zero/shuffled gap。 只是诊断，不直接提升模型。
P0 High-noise reweighting 高噪声区 condition 信号弱。 提高 t=0~0.3 采样和 loss 权重；单独记录该区间指标。 可能牺牲低噪声精修或整体 loss 曲线。
P0 Prefix continuation pretrain 无条件 pretrain 没训练 prompt-conditioned routing。 从普通 text corpus 切 prefix/continuation，走现有 conditional mask 管线。 切分策略、长度分布和 EOS 控制会影响结果。
P0 Endpoint / token-aware loss latent L2 接近不等于 token 正确。 在高噪声 x_pred 上加 CE(DLM(x_pred), target_tokens)。 Short QA 10K 已验证有效；下一步风险主要是 full SFT 的长答案和数据混合。
P1 x/v accounting probes 区分 endpoint 预测错，还是 rollout 积分把正确 endpoint 走坏。 同时记录 x_pred direct decode、转换后的 v_pred step 误差、最终 trajectory decode。 只是诊断；如果 DLM 对 rough latent 不鲁棒，需要和下一项一起看。
P1 DLM robustness probe 确认 DLM 是否能评价 noisy / rough latent。 扫 x0 + sigma * noise 的 decode token acc；必要时先 finetune DLM head。 如果 DLM 本身不鲁棒，token-aware loss 要先 warmup。
P2 Trajectory / rollout training 训练 state 与推理 state 不一致。 把 teacher rollout 或 self-rollout 中间状态加入训练，做 trajectory consistency。 训练成本上升，teacher 轨迹质量会限制上限。
P2 Shortcut / stride-conditioned ELF 局部速度场不适合少步/一步生成。 给模型加 stride token，训练 model(z,t,d) 预测多步后状态或终点。 模型和训练目标改动更大，需要小规模验证。

这组结果说明，问题确实集中在 early high-noise endpoint semantics。 单纯提高高噪声采样或 decoder probability 只能把 t=0.1 correct 从 0.53 拉到 0.63-0.67； 直接对高噪声 x_pred 加 token-level CE 后，controlled denoise 接近饱和，同时 zero/shuffled prompt 仍接近 0，说明提升不是 decoder shortcut，而是 prompt-conditioned semantic routing 被显式监督到了。
当前结果来自 Tulu Short QA 10K 和 16 条 trajectory probe，足以决定算法方向，但还不能直接代表 full SFT。 下一步应把 denoiser_p_mean=-3、decoder_prob=0.50、 semantic_ce_weight=0.50、semantic_ce_t_max=0.30 作为主设置跑全量 SFT； decoder_prob=0.25 保留为 trajectory-stable control。

建议下一组实验

  1. 直接启动 full Tulu SFT scale-up：主线使用 denoiser_p_mean=-3、decoder_prob=0.50、 semantic_ce_weight=0.50、semantic_ce_t_max=0.30。
  2. 保留一条 decoder_prob=0.25 的缩小版或中等规模 control，用来判断 full SFT 上 trajectory stability 是否仍然受 decoder branch 比例影响。
  3. 每个关键 checkpoint 固定跑同一套 harness：clean decode、controlled denoise、zero/shuffled gap、 t_start=0 uniform/logit-tail trajectory，以及按 source / answer type / length 的 slice。
  4. 如果 full SFT 对长答案或 mixed length 退化，再做 data recipe ablation： short answer vs mixed length、source mix、target length bucket、EOS/length policy。
  5. Prefix continuation pretrain 先降为第二阶段增强项。只有当 full SFT 仍然出现 prompt-conditioned routing 不稳时，再用大规模 prefix continuation 去补 conditional transport 的底座。
  6. 多模态 Stage 1 / Stage 2 仍然等 text-only full SFT 稳定后再接；否则会把同一个 high-noise semantic routing 问题迁移到图文条件上。
多模态 Stage 1 / Stage 2 应该等 text-only conditional flow 在真实短答和混合长度子集上稳定后再继续。 否则图文训练只会把“会生成文本但不按条件回答”的问题换成“会生成文本但不按图回答”。
