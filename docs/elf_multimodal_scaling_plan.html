ELF 多模态训练规模化路线与数据调查

记录当前 ELF 文本与多模态训练的瓶颈、上海侧可用数据资产、SFT/overfit/ablation 诊断结果，以及下一阶段可落地路线。 本文更新于 2026-05-31，重点加入 full Tulu3 SFT、synthetic short QA、Tulu3 Short QA 10K 和 Tulu3 Mixed Length 10K 的诊断统计。

结论摘要

652M 当前 ELF-L 参数量

不包含 frozen T5-small encoder。B/M/L 约为 105M / 343M / 652M。

~30B 当前 OWT checkpoint 的 padded token 量级

按 checkpoint_57051、global batch 512、context 1024 粗算，约 29.9B token positions。

12T+ 上海侧最大文本候选数据

`38b_solar_0320_fix_anwser_mmdata` 是目前看到的最大纯文本候选，但需要质量过滤。

t=0 SFT 后完整采样仍会崩

checkpoint_5402 的 clean decode 正常，低噪声修复正常，但从纯噪声 reverse 时 prompt/target 对齐失败。

0.992 短 QA overfit 已打通高噪声采样

128 条短答案从 t=0 纯噪声 reverse，uniform / logit-tail token acc 均为 0.9922。

10K 三组 10K 消融已完成

Synthetic 10K 基本可训通；Tulu Short 和 Tulu Mixed 暴露真实分布、长度和采样轨迹问题。

核心判断： 当前多模态效果弱不只是“缺一轮 SFT”。Tulu3 SFT 已经能让 decoder 从真实 target latent 几乎无损还原文本，也能在低噪声区域利用 prompt 做局部修复； 但在真实 SFT 分布上，从纯噪声开始的全局 reverse trajectory 仍会很快进入错误语义盆地。 进一步的短答案 overfit 证明：当前 ELF 架构并非天然无法从高噪声按 prompt 回到 target；问题更可能出在真实 SFT 的数据复杂度、目标权重、答案边界/长度建模和高噪声 conditional vector field 学习不足。 10K ablation 进一步说明：纯合成短 QA 可以学到从纯噪声到答案的条件场，但迁移到真实 Tulu 分布后，低/中噪声 denoise 与多步 sampling 之间仍有明显 gap。 因此下一步不是直接开更大的多模态训练，而是先把 text-only flow 的高噪声 instruction generation、数据 curriculum、采样和目标权重稳定下来。

SFT 诊断实验结果（2026-05-30）

本节记录 32GPU Tulu3 SFT 结束后的诊断结果。所有 probe 文件已放在仓库 eval_probes/ 下，主要使用 outputs/elf_l-tulu3-sft-t5-1024-hope-32gpu/checkpoint_5402 的 raw params； EMA 在短 SFT 后局部指标更弱，因此当前诊断优先看 raw params。

直接从噪声完整采样 32/64 step ODE/SDE 都能生成英文文本，但经常答非所问，训练集短样本也不稳定。 “会说话”不等于“按 prompt 生成 target”。完整 reverse trajectory 没有被 SFT 打通。
CleanNet decode sanity 真实 target latent 直接经 decoder 还原：seen-style train short 平均 token acc 99.57%，自造 instruction probe 为 100%。 latent-to-token decoder 没有崩，T5 latent 本身可以被当前 head 解回 target。

当前最可能原因： SFT 的 CE 分支主要训练 latent decoder，而不是像 AR LM 那样直接教模型从 prefix 自回归生成答案； L2/flow 分支虽然能在靠近 target 的局部区域修复，但高噪声区的 conditional vector field 没有学到稳定指向 target answer manifold 的全局方向。 换句话说，instruction tuning 的文本监督进来了，但没有充分变成“从随机 latent 出发也能按 prompt 走到正确答案”的 flow 能力。
  • 可能原因 1：高噪声区域 condition 信号太弱，第一步 x_pred 已经落到错误语义盆地，后续 ODE 只是沿着错误方向积分。
  • 可能原因 2：当前 CE/L2 混合目标不等价于 AR SFT；CE 让 decoder 会读 latent，但不保证 denoiser 从噪声生成对应 latent。
  • 可能原因 3：训练数据没有显式 EOS / target length 建模，add_special_tokens=False 可能让答案边界和短回答控制更难。
  • 可能原因 4：T5-small tokenizer/encoder 对中文和多轮指令并不理想，中文 probe 的 token acc 和文本可读性会被 tokenizer 质量放大影响。
  • 可能原因 5：短 SFT 后 EMA 滞后于 raw params；当前 checkpoint 诊断应优先用 raw params，EMA 只作为补充。
  • 可能原因 6：sampling schedule 是次要因素。uniform 和 logit-tail 在 t_start=0/0.1 都崩，说明主问题不是多加几步就能解决。
下一轮优先 sanity： 不急着直接扩大多模态训练。短答案 overfit 已证明小规模可训通；下一轮应扩大到更丰富的短指令、多 token answer 和少量长回答， 显式保留 EOS/长度控制，并把 t_start=0 到 0.3 的高噪声 conditional trajectory 作为核心指标。 只有当 text-only flow 能在更接近真实 SFT 的分布上稳定从纯噪声按 prompt 生成 target，再继续接多模态 Stage 1/Stage 2 才更有意义。

短答案 Flow Overfit 实验结果（2026-05-30）

为了区分“Flow Matching 范式本身从高噪声无法生成”与“当前大规模 SFT 训练没有把高噪声条件场训好”， 在服务器本机 2 张 H100 上跑了一个 128 条英文短 QA 的 overfit 实验。该实验从 checkpoint_5402 raw params 初始化，保持 max_length=1024，对 target 显式追加 EOS， 使用短 prompt / 短答案来最大限度排除长文本、图像和复杂 instruction 分布的干扰。

训练配置 128 条 synthetic short QA；global batch 8；200 epochs；3200 steps；AdamW；lr=5e-5；decoder_prob=0.25；denoiser_p_mean=-2.0。 脚本：scripts/run_short_qa_overfit_local.sh；配置：src/configs/training_configs/train_short_qa_overfit_ELF-L_local_2gpu.yml。
运行资源 2 张 H100，本机直接跑；训练速度约 2.2 steps/sec；显存约 19.6G / 卡。 中间 checkpoint 写 DolphinFS 太慢，因此正式 run 使用 /tmp/elf-pro-cache 作为 output_dir。
最终 checkpoint /tmp/elf-pro-cache/short_qa_overfit_ELF-L_t5_1024_from_sft5402/checkpoint_3200，约 9.8G。 最终训练日志：loss=0.0492，l2=0.0114，ce=0.0817。

Sampling trajectory（16 条，多 t_start） t_start=0.95/0.70/0.50/0.30/0.10/0.00，uniform 和 logit-tail 均达到 final token acc = 1.000。 在小数据短答案分布上，从中低噪声到纯噪声都能被 reverse 回正确答案。

实验判断： 这个结果把问题边界向前推了一步：ELF-L + T5-small latent + 当前采样公式可以在小数据上学会高噪声 conditional generation。 因此主线不应立刻放弃 Flow Matching 范式，也不应把失败完全归因于模型参数量不够。 更合理的下一步是逐步增加 overfit 难度。2026-05-31 已经完成 Synthetic 10K、Tulu3 Short QA 10K 和 Tulu3 Mixed Length 10K 三组 ablation； 下面的统计显示，断点不在 clean decode，而在真实分布下的高噪声 conditional denoise 和多步 trajectory 稳定性。

样本级失败模式

  • Synthetic 10K 失败多是离散短答案漂移：例如 39 minus 10 期望 29 生成 23，Is 1129 even? 期望 no 生成 yes。
  • Tulu3 Short QA 失败常见于分类标签、数字、模板化 FLAN 任务：例如期望 No 生成 .，或期望 Completion D 生成 100%letion D。
  • Tulu3 Mixed 失败更像语义盆地偏移：长回答仍像同类任务的答案，但实体、标题、叙事开头或步骤细节不对；token acc 受长度累积影响明显。
  • 所有真实 Tulu ablation 的 clean decode 都接近 1.0，因此“解码头读不出 target latent”不是主因。
这一轮 ablation 的核心结论： 当前建模方式能够在简单合成分布上学习从高噪声到 target 的 conditional flow；真实 Tulu 分布失败并不是单一的 max length 或 decoder 问题。 更接近根因的是：真实 prompt 过长、答案类型离散且信息密度高、FLAN/Natural Instructions 风格占比过大、部分 source 的模板任务与 open-ended 对话混杂， 导致高噪声区的 vector field 学到的是“合理答案流形”而不是“当前 prompt 的唯一 target latent”。 Mixed Length 的结果还说明，局部 denoise 和全局多步采样要分开看：低噪声修复强，不代表从纯噪声可以稳定抵达同一个语义目标。
对后续训练的约束： 后续所有 text-only SFT / 多模态 SFT 都应该把 t_start=0 trajectory、zero/shuffled condition gap、短答案 exact、长答案语义相似度四类指标固定下来。 只看训练 loss、clean decode 或单步低噪声 denoise，会误判模型已经学会 instruction following。

推荐主路线

阶段 0：把诊断闭环固定下来

  • 保留当前 T5-small encoder 和 ELF-L checkpoint，先不引入多模态变量。
  • 每个 checkpoint 固定输出四类指标：clean decode、controlled denoise、sampling trajectory、zero/shuffled condition gap。
  • 短答案 128 条和 Synthetic 10K 证明当前架构可在简单分布上从 t=0 高噪声按 prompt 生成 target。
  • Tulu Short / Mixed 说明真实分布下仍存在高噪声条件场和多步 trajectory gap，不能只看 loss 或 clean decode。
  • 下一步先补更细的诊断统计：按 source、prompt length、target length、答案类型、模板任务/开放对话分别切分 probe 结果。
  • 当 text-only 从纯噪声能在真实短答和混合长度子集上稳定生成 target，再接回多模态 Stage 1 / Stage 2。

阶段 1：做真实分布的 recipe ablation

  1. 主数据先用 Tulu Short 10K / Mixed 10K，不再直接用 full Tulu3 做盲训。
  2. 优先试高噪声区加权：调整 timestep 分布、增加 t=0/0.1 附近的 denoise 监督，或加入 trajectory consistency 类辅助目标。
  3. 对比 decoder_prob=0.25、0.5 和更低 CE 比例，确认 CE 是帮助 decoder 还是挤占 denoiser 的高噪声学习。
  4. 把 FLAN/Natural Instructions、open-ended chat、math/label、拒答/安全类样本拆开训练小模型，确认哪类 source 最容易让 vector field 漂移。
  5. 采样侧对比 uniform/logit-tail、32/64/128 steps、ODE/二阶 solver；但只有当 controlled denoise 提升后，采样优化才可能成为主收益。

阶段 2：构建更强 text pretrain corpus

  1. 从 `38b_solar` 和 `experiment_1997` 各抽样 10k 到 100k 条，做语言、长度、重复率、乱码率、URL/HTML 比例、代码比例、问答格式比例统计。
  2. 先构建一个 50B 到 100B token positions 的 text pretrain 子集，不直接吃完整 12T。
  3. 统一转换为当前 ELF loader 可读的 Arrow 格式：字段为 input_ids，max length 1024，T5 tokenizer。
  4. 训练一个 stronger text checkpoint，保留 OWT checkpoint 作为初始化，对比从零训练和继续训练两种方式。

阶段 3：Text SFT 和多模态训练

  1. 用 recipe ablation 选出的设置重新训练 text SFT，再决定是否扩大到 full Tulu3。
  2. 用更强 text checkpoint 初始化 Tulu3 SFT，decoder_prob 不先拍脑袋固定为 0.5，而是以 high-noise trajectory 指标选型。
  3. 在 text-only SFT 后再进入多模态 Stage 1 projector warmup。
  4. Stage 2 多模态 instruction 从 text-SFT checkpoint 初始化，并加载 Stage 1 projector。
  5. 多模态评估必须加入 shuffled-image control，避免只看 caption-like 输出误判模型真的用图。

关于换 Encoder 的判断

不建议把 encoder 替换作为当前主线第一步。 这个项目不是普通 AR LM，ELF 在 frozen encoder latent space 里做 flow matching，并且 decoder head 要从 latent 解回 token。 一旦换 encoder，latent 分布、hidden size、tokenizer、decoder head、latent mean/std、text checkpoint 和多模态 projector 都会受到影响。
方案 兼容性 预期收益 建议
T5-small 继续 scale 最高，现有 checkpoint 可复用。 主要提升来自数据量和训练步数。 主线 先把范式训通。
T5-v1.1-small hidden size 接近，改动相对可控，但 latent 分布仍变。 可能获得更干净的 encoder 表征。 pilot 可以单独小规模验证。
T5-base / T5-large / UL2 hidden size 变化，模型输入/输出层和 checkpoint 兼容性差。 encoder 容量更高，上限更高。 下一代 需要重训成本预算。
BGE / E5 等 sentence encoder 不适合作为直接替换。 句向量强，但 token-level generation latent 不匹配。 不推荐 除非重新设计目标。
