ELF 多模态训练规模化路线与数据调查

记录当前 ELF 文本与多模态训练的瓶颈、上海侧可用数据资产、下一阶段可落地路线，以及更激进的 encoder / 模型规模化试验方向。 本文基于 2026-05-30 对代码库、HOPE 配置和上海 DolphinFS 存储的调查。

结论摘要

652M 当前 ELF-L 参数量

不包含 frozen T5-small encoder。B/M/L 约为 105M / 343M / 652M。

~30B 当前 OWT checkpoint 的 padded token 量级

按 checkpoint_57051、global batch 512、context 1024 粗算，约 29.9B token positions。

12T+ 上海侧最大文本候选数据

`38b_solar_0320_fix_anwser_mmdata` 是目前看到的最大纯文本候选，但需要质量过滤。

t=0 SFT 后完整采样仍会崩

checkpoint_5402 的 clean decode 正常，低噪声修复正常，但从纯噪声 reverse 时 prompt/target 对齐失败。

核心判断： 当前多模态效果弱不只是“缺一轮 SFT”。Tulu3 SFT 已经能让 decoder 从真实 target latent 几乎无损还原文本，也能在低噪声区域利用 prompt 做局部修复； 但从纯噪声开始的全局 reverse trajectory 仍会很快进入错误语义盆地。 因此下一步需要同时解决两件事：一是把 text pretrain 数据和 token budget scale 上去，二是针对 continuous flow matching 的高噪声 conditional generation 做专门诊断和训练改造。

SFT 诊断实验结果（2026-05-30）

本节记录 32GPU Tulu3 SFT 结束后的诊断结果。所有 probe 文件已放在仓库 eval_probes/ 下，主要使用 outputs/elf_l-tulu3-sft-t5-1024-hope-32gpu/checkpoint_5402 的 raw params； EMA 在短 SFT 后局部指标更弱，因此当前诊断优先看 raw params。

诊断项 观测结果 判断
直接从噪声完整采样 32/64 step ODE/SDE 都能生成英文文本，但经常答非所问，训练集短样本也不稳定。 “会说话”不等于“按 prompt 生成 target”。完整 reverse trajectory 没有被 SFT 打通。
CleanNet decode sanity 真实 target latent 直接经 decoder 还原：seen-style train short 平均 token acc 99.57%，自造 instruction probe 为 100%。 latent-to-token decoder 没有崩，T5 latent 本身可以被当前 head 解回 target。
Controlled denoise sanity 从 target latent 加噪后单步预测，正确 prompt 明显优于 zero / shuffled prompt。instruction probe 在 t=0.5 时 x_mse 0.084 vs 0.184/0.188，t=0.3 时 0.153 vs 0.371/0.403。 模型在低到中噪声区能利用 condition，不是完全忽略 prompt。
Sampling trajectory probe 固定 prompt+target，从真实 target latent 加不同强度噪声再 reverse。t_start=0.5 以后基本还能局部修复；t_start=0.1 明显退化；t_start=0 几乎失败。 崩点在高噪声全局生成区，而不是最后 decode 或低噪声修复区。
Trajectory probe（5 条英文指令，raw params） logit-tail final acc / mse uniform final acc / mse 结论
t_start=0.95 0.838 / 0.098 0.829 / 0.050 极低噪声下基本可恢复。
t_start=0.70 0.838 / 0.101 0.826 / 0.191 低噪声修复稳定。
t_start=0.50 0.823 / 0.120 0.834 / 0.242 仍能保住主要语义，但输出开始有局部词错。
t_start=0.30 0.687 / 0.281 0.752 / 0.359 进入不稳定区，部分样本还能恢复，部分已偏离。
t_start=0.10 0.304 / 0.840 0.324 / 0.822 高噪声语义锚定失败，生成内容开始泛化到无关答案。
t_start=0.00 0.000 / 1.136 0.005 / 1.154 从纯噪声采样基本失败；uniform 和 logit-tail 都失败，说明不是单纯 timestep 离散化问题。
当前最可能原因： SFT 的 CE 分支主要训练 latent decoder，而不是像 AR LM 那样直接教模型从 prefix 自回归生成答案； L2/flow 分支虽然能在靠近 target 的局部区域修复，但高噪声区的 conditional vector field 没有学到稳定指向 target answer manifold 的全局方向。 换句话说，instruction tuning 的文本监督进来了，但没有充分变成“从随机 latent 出发也能按 prompt 走到正确答案”的 flow 能力。
  • 可能原因 1：高噪声区域 condition 信号太弱，第一步 x_pred 已经落到错误语义盆地，后续 ODE 只是沿着错误方向积分。
  • 可能原因 2：当前 CE/L2 混合目标不等价于 AR SFT；CE 让 decoder 会读 latent，但不保证 denoiser 从噪声生成对应 latent。
  • 可能原因 3：训练数据没有显式 EOS / target length 建模，add_special_tokens=False 可能让答案边界和短回答控制更难。
  • 可能原因 4：T5-small tokenizer/encoder 对中文和多轮指令并不理想，中文 probe 的 token acc 和文本可读性会被 tokenizer 质量放大影响。
  • 可能原因 5：短 SFT 后 EMA 滞后于 raw params；当前 checkpoint 诊断应优先用 raw params，EMA 只作为补充。
  • 可能原因 6：sampling schedule 是次要因素。uniform 和 logit-tail 在 t_start=0/0.1 都崩，说明主问题不是多加几步就能解决。
下一轮优先 sanity： 不急着直接扩大多模态训练。先做短答案、小数据 overfit，显式加入 EOS/长度控制，并把 t_start=0 到 0.3 的高噪声 conditional trajectory 作为核心指标。 只有当 text-only flow 能稳定从纯噪声按 prompt 生成 target，再继续接多模态 Stage 1/Stage 2 才更有意义。

推荐主路线

阶段 0：先把 text-only flow 的 instruction generation 打通

  • 保留当前 T5-small encoder 和 ELF-L checkpoint，先不引入多模态变量。
  • 基于本次 checkpoint_5402 的诊断，优先做短答案 overfit、EOS/长度建模和高噪声 trajectory sanity。
  • 继续使用 CleanNet decode、Controlled denoise、Sampling trajectory 三类 probe 作为每轮训练后的固定报告。
  • 当 text-only 从纯噪声能按 prompt 稳定生成 target，再接回多模态 Stage 1 / Stage 2。

阶段 1：构建更强 text pretrain corpus

  1. 从 `38b_solar` 和 `experiment_1997` 各抽样 10k 到 100k 条，做语言、长度、重复率、乱码率、URL/HTML 比例、代码比例、问答格式比例统计。
  2. 先构建一个 50B 到 100B token positions 的 text pretrain 子集，不直接吃完整 12T。
  3. 统一转换为当前 ELF loader 可读的 Arrow 格式：字段为 input_ids，max length 1024，T5 tokenizer。
  4. 训练一个 stronger text checkpoint，保留 OWT checkpoint 作为初始化，对比从零训练和继续训练两种方式。

阶段 2：Text SFT 和多模态训练

  1. 用更强 text checkpoint 初始化 Tulu3 SFT，继续使用 CE/L2 各半的 decoder_prob=0.5。
  2. 在 text-only SFT 后再进入多模态 Stage 1 projector warmup。
  3. Stage 2 多模态 instruction 从 text-SFT checkpoint 初始化，并加载 Stage 1 projector。
  4. 多模态评估必须加入 shuffled-image control，避免只看 caption-like 输出误判模型真的用图。

关于换 Encoder 的判断

不建议把 encoder 替换作为当前主线第一步。 这个项目不是普通 AR LM，ELF 在 frozen encoder latent space 里做 flow matching，并且 decoder head 要从 latent 解回 token。 一旦换 encoder，latent 分布、hidden size、tokenizer、decoder head、latent mean/std、text checkpoint 和多模态 projector 都会受到影响。
方案 兼容性 预期收益 建议
T5-small 继续 scale 最高，现有 checkpoint 可复用。 主要提升来自数据量和训练步数。 主线 先把范式训通。
T5-v1.1-small hidden size 接近，改动相对可控，但 latent 分布仍变。 可能获得更干净的 encoder 表征。 pilot 可以单独小规模验证。
T5-base / T5-large / UL2 hidden size 变化，模型输入/输出层和 checkpoint 兼容性差。 encoder 容量更高，上限更高。 下一代 需要重训成本预算。
BGE / E5 等 sentence encoder 不适合作为直接替换。 句向量强，但 token-level generation latent 不匹配。 不推荐 除非重新设计目标。
